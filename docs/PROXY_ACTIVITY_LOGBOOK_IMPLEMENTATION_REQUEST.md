# Proxy Activity and Logbook Implementation Request

| ID | Area | Required proxy-side implementation | Exact contract, behavior, and acceptance criteria |
|---:|---|---|---|
| 1 | Objective | Add sanitized request-lifecycle telemetry for the dashboard's **Activity** page and durable, searchable daily history for its **Logbook** page. | This work is limited to public inference request activity, the four authenticated admin read endpoints described below, SSE delivery, redacted JSONL persistence, retention, and tests. Do not add prompt/body capture, response capture, analytics, mutation endpoints, or browser-facing authentication. |
| 2 | Frontend source of truth | Implement the wire contract consumed by the web app's `ProxyRequestRecord`, `ActivitySnapshot`, `ActivityEvent`, `ActivityLogDatesResponse`, and `ActivityLogResponse` types. | JSON property names are camelCase and enum strings are exact. Unknown or renamed fields will not be rendered. Optional fields may be omitted or `null`; required fields must always be present. |
| 3 | Authentication | Put all four endpoints below the proxy's existing admin/API-key middleware. | Accept the proxy key using the proxy's established authentication rules (`Authorization: Bearer <PROXY_API_KEY>` and, if already supported globally, `X-API-Key: <PROXY_API_KEY>`). Return the proxy's normal 401/403 response on failure. The activity/log endpoints themselves must never be public. |
| 4 | Tracked traffic scope | Track public inference requests only, not health, admin, model-listing, device-login, or the telemetry endpoints themselves. | At minimum track `POST /v1/completions`, `POST /v1/chat/completions`, `POST /v1/responses`, `POST /v1/responses/compact`, `POST /v1/images/generations`, `POST /v1/images/edits`, and `POST /v1/messages`. If WebSocket inference on `GET /v1/responses` is instrumented, it must use the same record contract and finish exactly once when the socket session ends. Route values must be stable route templates/paths, never URLs containing query strings or user-provided path data. |
| 5 | Request identity | Use the proxy's existing request ID as the telemetry record ID. | `id` is a non-empty string, unique for the retained live window and durable history. Preserve an accepted `X-Request-Id` if that is existing proxy behavior; otherwise use the generated proxy request ID. Never use a prompt, token, account credential, or upstream authorization value as an ID. |
| 6 | Record field: `id` | Required string. | Example: `"req_1726776000000000000_00000001"`. It is displayed, searched by Logbook `q`, and used as the Activity reducer key. Every update for one request must retain the same value. |
| 7 | Record field: `startedAt` | Required UTC timestamp string set once when request tracking begins. | Use RFC 3339/RFC 3339 Nano, e.g. `"2026-09-19T20:00:00.123456Z"`. It determines Activity ordering and the historical file/day. Never change it during updates. |
| 8 | Record field: `endedAt` | Optional UTC timestamp string. | Omit or return `null` while active. Set once at terminal completion. Use RFC 3339/RFC 3339 Nano. The Activity client removes a terminal record locally 60 seconds after this time if it misses the server's `remove` event. |
| 9 | Record field: `route` | Required sanitized route string. | Examples: `"/v1/responses"`, `"/v1/chat/completions"`. Do not include query parameters, hostnames, request bodies, user text, file names, or arbitrary raw URLs. Start with the request path and replace it with the framework route template on completion if available. |
| 10 | Record field: `model` | Optional sanitized model string populated after safe request decoding/normalization. | Example: `"gpt-5.6-terra"`. Omit or return `null` until known. Trim whitespace and cap stored/displayed metadata values at 200 characters. Do not retain the rest of the request body. |
| 11 | Record fields: `accountId`, `accountLabel` | Optional selected proxy-account metadata populated when routing selects an account. | Both are strings; omit or return `null` until known. `accountId` is the proxy's internal safe account identifier, not an OAuth token or credential. `accountLabel` is the configured display label. Trim and cap each at 200 characters. The UI prefers `accountLabel`, then `accountId`. |
| 12 | Record field: `phase` | Required lifecycle enum. | Exact values: `routing`, `upstream`, `streaming`, `finalizing`, `complete`. Start at `routing`; move to `upstream` once an account/upstream attempt is selected; use `streaming` once downstream streaming begins; use `finalizing` while assembling/writing a non-stream response or terminal frame; always set `complete` before publishing/persisting the terminal record. Do not invent additional values. |
| 13 | Record field: `outcome` | Required lifecycle result enum. | Exact values: `active`, `succeeded`, `failed`, `cancelled`, `timed_out`. It is `active` from start through all nonterminal updates. Terminal mapping: successful status/end=`succeeded`; client cancellation=`cancelled`; configured request/deadline timeout=`timed_out`; upstream, stream, validation, auth, routing, or server failure=`failed`. A status `>=400` defaults to `failed` unless an explicit cancellation/timeout classification is available. |
| 14 | Record field: `status` | Optional final downstream HTTP status integer. | Omit or return `null` while unknown/active. Set to the status actually sent to the caller at completion. For upgraded WebSocket traffic, document and consistently use the initial handshake status or omit it; do not fabricate an HTTP status for later socket messages. |
| 15 | Record field: `durationMs` | Optional non-negative integer duration in milliseconds. | Omit or return `null` while active. At completion calculate `max(endedAt-startedAt, 0)` using the proxy clock. The frontend computes a live duration itself until this field is present. |
| 16 | Record fields: `errorCode`, `errorMessage` | Optional safe terminal failure metadata. | `errorCode` is a bounded internal classification such as `client_canceled`, `request_timeout`, `rate_limited`, `quota_exhausted`, `no_available_accounts`, `model_not_found`, `invalid_api_key`, `authentication_error`, `invalid_request_error`, `invalid_json`, `upstream_error`, `stream_error`, or `api_error`. `errorMessage` must be generated from an allowlisted code-to-safe-text mapping; never persist or stream a raw error. Recommended mapping: cancellation→`client canceled request`; timeout→`request timed out`; rate limit→`all eligible accounts are rate limited`; quota→`upstream account quota exhausted`; no account→`no available accounts`; missing model→`model not found`; authentication→`authentication failed`; bad input→`invalid request`; upstream/stream/API failure→`upstream request failed`; unknown non-empty failure→`request failed`. |
| 17 | Complete record example | Emit this shape for a finalized request. | <code>{<br>&nbsp;&nbsp;"id": "req_1726776000000000000_00000001",<br>&nbsp;&nbsp;"startedAt": "2026-09-19T20:00:00.000Z",<br>&nbsp;&nbsp;"endedAt": "2026-09-19T20:00:01.250Z",<br>&nbsp;&nbsp;"route": "/v1/responses",<br>&nbsp;&nbsp;"model": "gpt-5.6-terra",<br>&nbsp;&nbsp;"accountId": "acct_01",<br>&nbsp;&nbsp;"accountLabel": "primary",<br>&nbsp;&nbsp;"phase": "complete",<br>&nbsp;&nbsp;"outcome": "succeeded",<br>&nbsp;&nbsp;"status": 200,<br>&nbsp;&nbsp;"durationMs": 1250<br>}</code> |
| 18 | In-memory Activity store | Maintain the current live set in a concurrency-safe store keyed by `id`. | Start creates and publishes an active record. Update mutates only an existing active record and publishes the full updated record. Finish is idempotent: only the first finish of an active record may set terminal data, publish it, and append it to disk. Snapshot and subscription operations must be safe under concurrent requests. Sort snapshots newest `startedAt` first. |
| 19 | Live terminal retention | Keep completed records in the Activity store for 60 seconds after `endedAt`, then remove them. | A sweep may run every 30 seconds; exact removal can therefore occur shortly after the 60-second boundary. Removing a record must publish a `remove` event. Also prune before returning a snapshot or establishing a subscription so expired records are not resurrected. In-flight records have no 60-second expiry. The live store is memory-only and may be empty after restart. |
| 20 | Event ordering/race rule | Every snapshot and mutation must carry a server-generated UTC `emittedAt` timestamp that can be compared chronologically. | The web app starts the REST snapshot and SSE connection concurrently and rejects a snapshot older than an already-applied stream event. Therefore `emittedAt` must be RFC 3339-compatible, reflect event creation time, and never be copied from `startedAt`. A newly opened SSE subscription must atomically capture its initial snapshot and register for subsequent events so there is no snapshot/subscription gap. |
| 21 | Endpoint: Activity snapshot | Implement `GET /admin/requests/activity`. | Request: no query/body. Success: HTTP 200, `Content-Type: application/json`, `Cache-Control: no-store`. Body: <code>{<br>&nbsp;&nbsp;"requests": [/* ProxyRequestRecord[] */],<br>&nbsp;&nbsp;"emittedAt": "2026-09-19T20:00:03.000Z"<br>}</code> `requests` must be an empty array, not `null`, when no activity exists. |
| 22 | Endpoint: Activity SSE | Implement `GET /admin/requests/activity/stream`. | Request headers should accept `Accept: text/event-stream`; no body/query. Success: HTTP 200 with `Content-Type: text/event-stream; charset=utf-8`, `Cache-Control: no-cache, no-transform`, `Connection: keep-alive`, and `X-Accel-Buffering: no`. Flush headers and every event promptly. End cleanly when the request context is cancelled. Send an SSE comment heartbeat such as `: keep-alive\n\n` every 15 seconds so intermediaries do not close an idle stream. |
| 23 | SSE first event: `snapshot` | Every new SSE connection must begin with the subscription's atomic snapshot. | Exact frame: <code>event: snapshot<br>data: {"type":"snapshot","snapshot":{"requests":[],"emittedAt":"2026-09-19T20:00:03Z"}}<br><br></code> The `data` value is one JSON object. The inner snapshot has the same shape as the REST response. |
| 24 | SSE mutation event: `upsert` | Send on start, every meaningful lifecycle/metadata update, and terminal completion. | Exact frame: <code>event: upsert<br>data: {"type":"upsert","record":{/* full ProxyRequestRecord */},"emittedAt":"2026-09-19T20:00:04Z"}<br><br></code> Always send the complete current record, not a partial patch. The client replaces the record by `record.id`. |
| 25 | SSE mutation event: `remove` | Send when a terminal record ages out of the live window. | Exact frame: <code>event: remove<br>data: {"type":"remove","id":"req_...","emittedAt":"2026-09-19T20:01:05Z"}<br><br></code> The frontend also accepts ordinary unnamed `message` events, but named `snapshot`, `upsert`, and `remove` events are required. |
| 26 | SSE slow-client behavior | A slow or disconnected subscriber must not block request processing or other subscribers. | Use a bounded per-subscriber buffer (64 events is sufficient). Publish non-blockingly. If a subscriber's queue is full, unregister/close that subscriber; browser `EventSource` will reconnect and receive a fresh snapshot. Never hold an activity-store lock while performing network I/O. |
| 27 | Durable log write | Append exactly one finalized, redacted record as one JSON line after a request finishes. | File path: `${DATA_DIR}/request-YYYY-MM-DD.jsonl`, where the date is the UTC date of `startedAt` (not completion time). Open with create+append+write semantics and file mode `0600`; serialize one compact JSON object followed by `\n`. Serialize only `ProxyRequestRecord` fields. Coordinate concurrent writers so lines cannot interleave. A request must not be written on each update, and must not be written twice if finish is called twice. |
| 28 | Durable log safety | Telemetry must remain useful if a file contains a malformed/truncated line. | Log reads should skip lines that fail record JSON decoding and continue returning valid lines; return an error only for actual file/scanner I/O failure. Support lines up to at least 4 MiB even though properly sanitized records should be much smaller. A missing day's file is not an error and returns an empty page. |
| 29 | Historical retention | Retain 30 UTC daily files including the current UTC day. | On Activity-store startup and periodic housekeeping, remove only files matching `request-YYYY-MM-DD.jsonl` whose parsed date is older than `today UTC - 29 days`. Do not touch unrelated files in `${DATA_DIR}`. Keep account/model persistence intact. |
| 30 | Endpoint: Log dates | Implement `GET /admin/requests/logs/dates`. | Request: no query/body. Success: HTTP 200, `Cache-Control: no-store`. Body: <code>{<br>&nbsp;&nbsp;"days": [{"date":"2026-09-19","total":42,"failed":3}],<br>&nbsp;&nbsp;"fetchedAt":"2026-09-19T20:05:00Z"<br>}</code> Include only valid retained request-log files. `date` is `YYYY-MM-DD`; `total` counts all valid records; `failed` counts outcomes `failed` plus `timed_out` (not `cancelled`). Sort days newest first. Return `days: []` when none exist. |
| 31 | Endpoint: Log query | Implement `GET /admin/requests/logs`. | Required query: `date=YYYY-MM-DD`. Optional: `limit`, `cursor`, `q`, `outcome`, `account`, `model`. There is no request body. Example: `/admin/requests/logs?date=2026-09-19&limit=50&outcome=failed&account=primary&model=terra&q=upstream&cursor=NTA`. Apply all supplied filters with AND semantics before pagination. |
| 32 | Log query validation | Validate at the proxy boundary even though the web server also validates. | `date`: exact real calendar date in `YYYY-MM-DD`, otherwise HTTP 400 `invalid_date`. `limit`: default 50, integer 1–100, otherwise 400 `invalid_limit`. `outcome`: empty or one of `active`, `succeeded`, `failed`, `cancelled`, `timed_out`, otherwise 400 `invalid_outcome`. Each of `cursor`, `q`, `account`, `model`: maximum 200 characters, otherwise 400 `invalid_filter`. Malformed/out-of-range cursor: 400 `invalid_cursor`. |
| 33 | Filter semantics | Filters are case-insensitive substring matches after trimming the query value. | `outcome` is exact enum equality. `account` searches `accountId + " " + accountLabel`. `model` searches `model`. `q` searches the combined safe metadata fields `id`, `route`, `model`, `accountId`, `accountLabel`, `errorCode`, `errorMessage`, and `outcome`. Never search request/response content because it must not be retained. Historical logs normally contain terminal outcomes only; accepting `outcome=active` is harmless and normally returns no records. |
| 34 | Log ordering and cursor | Return newest records first and treat `cursor` as opaque to the client. | Read the day's append-order records, reverse them, apply filters, then paginate. A simple implementation is the URL-safe unpadded Base64 encoding of the decimal offset (`0`, `50`, etc.). Decode failure, negative offset, or offset beyond the filtered result length is `invalid_cursor`. The cursor is valid only for the same date/filter set; the frontend resets pagination when filters change. |
| 35 | Endpoint: Log response | Return the selected page and only include a next cursor when more filtered records remain. | Success: HTTP 200, `Cache-Control: no-store`. Body: <code>{<br>&nbsp;&nbsp;"date":"2026-09-19",<br>&nbsp;&nbsp;"records":[/* ProxyRequestRecord[] */],<br>&nbsp;&nbsp;"nextCursor":"NTA",<br>&nbsp;&nbsp;"fetchedAt":"2026-09-19T20:05:00Z"<br>}</code> `records` must be an array. Omit `nextCursor` or return `null` on the last page. For a valid date with no file/matches, return 200 with `records: []`. |
| 36 | Admin error format | Use one consistent JSON error shape for validation and server failures. | Follow the proxy's existing admin convention: HTTP status plus `{"error":"<stable_code>","message":"<safe explanation>"}`. Required stable codes: `invalid_date`, `invalid_limit`, `invalid_outcome`, `invalid_filter`, `invalid_cursor`, and `request_logs_failed`. Never put raw persisted lines, tokens, request bodies, upstream bodies, or filesystem secrets in the message. |
| 37 | Redaction boundary | Treat the Activity store as a strict metadata-only security boundary. | Forbidden in memory events and JSONL: request bodies, response bodies, prompts/messages/input, tool arguments/results, images/files/base64 data, cookies, authorization/API/OAuth headers, access/refresh tokens, raw upstream error payloads, stack traces, client IP, user-agent, and arbitrary query strings. Do not copy generic structured logger attributes wholesale. Populate each allowed field explicitly. |
| 38 | Failure isolation | Telemetry must not break inference traffic. | A subscriber failure must not affect requests. A persistence append error should be logged server-side with request ID and returned from the store to the caller/middleware for logging, but must not rewrite a successful inference response into an error. Read-endpoint storage failures may return 500 `request_logs_failed`. Activity snapshot/SSE store access should remain available independently of a damaged historical file. |
| 39 | Suggested Go package/file layout | Keep storage/event mechanics separate from HTTP handlers and request instrumentation. | Suggested integration: `internal/activity/store.go` for enums, records, concurrency, subscriptions, JSONL, filters, cursors, and retention; `internal/middleware/request_activity.go` for tracked-route middleware and safe setters; `internal/server/activity.go` for the four admin handlers/SSE framing; `internal/server/routes.go` for protected routes; `internal/server/app.go` for store construction and housekeeping. Reuse existing request ID, error classification, selected-account context, and logger helpers. |
| 40 | Instrumentation points | Add explicit, low-risk setters where metadata becomes known. | After normalization: set model. After account selection/failover: set the currently selected account and phase `upstream`. When downstream streaming starts: set `streaming`. Before final non-stream serialization or terminal stream frame: set `finalizing`. In middleware after handler completion: classify outcome/status, set `complete`, compute end/duration, publish, and append. Ensure early decode/auth/routing errors still finish the record if they are in the tracked public-route scope. |
| 41 | Store unit tests | Add deterministic tests with an injectable clock/temp directory. | Prove: start/update/finish emits full upserts; terminal fields and duration are correct; raw secret text passed as an error never appears in event/snapshot/file; exactly one JSONL line is written; duplicate finish does not duplicate; snapshot ordering is newest first; terminal records remain then expire; expiry emits remove; date counts include failed+timed_out; filters are case-insensitive and ANDed; pagination/cursor works; missing files return empty; malformed lines are skipped; only files older than the 30-day window are pruned. |
| 42 | Middleware/integration tests | Exercise real routes or a small Gin test router. | Prove: only intended method/path pairs are tracked; admin/health endpoints are excluded; model/account/phase setters update the same ID; success, HTTP failure, client cancellation, and timeout map to correct outcomes; safe error messages replace raw errors; telemetry persistence failure does not alter the inference response. |
| 43 | HTTP contract tests | Test all four authenticated endpoints. | Prove: missing/bad key is rejected; snapshot has `requests` and `emittedAt`; SSE content type/headers are correct and its first frame is a named `snapshot`; subsequent upsert/remove frames contain the required wrapper; heartbeat is a comment; date list is newest first; valid log filters/pagination work; invalid date/limit/outcome/filter/cursor return the documented 400 code; valid missing day returns 200 empty; all successful read responses carry `Cache-Control: no-store` (SSE uses `no-cache, no-transform`). |
| 44 | Frontend compatibility acceptance | Run a manual end-to-end check with the subscription-usage web app. | Open Activity, make one public inference request, and observe `routing`/later phases without refresh. Confirm the terminal result remains visible for about one minute and then disappears. Disconnect/reconnect the SSE stream and confirm the first snapshot restores current state without losing a newer event to the concurrent REST snapshot. Open Logbook, confirm the newest UTC day is selected, counts match, search/account/model/outcome filters work, Next/Previous use cursors correctly, and no sensitive payload content appears anywhere. |
| 45 | Definition of done | Deliver code, tests, and concise proxy README notes. | All Go tests pass, race-sensitive store tests pass under `go test -race` where practical, formatting/static checks pass, the four endpoints match this table byte-for-byte in field/enumeration names, inference behavior is unchanged, `${DATA_DIR}` contains only redacted finalized records, and the Activity/Logbook pages work without frontend contract changes. |
